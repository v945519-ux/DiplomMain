# Обновление дизайна Pizza-Tango

Изменения внесены в существующий Next.js-проект, без новых зависимостей.

- Светлая кремовая палитра, общие цвета, радиусы, отступы и тени в `client/app/globals.css`.
- Единая шапка и компактный подвал на всех активных маршрутах.
- Hero с существующей фотографией пиццы, оптимизированной в WebP (101 068 байт).
- Карточки, фильтры, корзина, профиль, формы входа и регистрации, страница товара оформлены в одном стиле.
- Убраны постоянно движущиеся декорации, анимированные градиенты и тяжёлое свечение. Hover карточки: −4 px; изображение: 1.03; переходы: 180–240 мс. Поддержан reduced motion.
- Добавлены keyboard focus, ссылка пропуска навигации, доступные подписи избранного, состояния ожидания.
- На странице товара устранены второй header/footer и обращение к отсутствующему CartProvider. Использован существующий API корзины и событие cart:changed.
- Добавлены недостающие клиентские метод product(slug) и тип ProductDetail согласно существующему Django endpoint. Исправлено устаревшее имя типа в старом компоненте профиля. Серверные маршруты и контракты не изменялись.

В исходниках нет контактного телефона, адреса пиццерии или соцсетей. Вымышленные контакты не добавлены; сохранён имеющийся график работы.

## Проверка

- ESLint: успешно.
- TypeScript: успешно.
- Production build: успешно.
- Браузер: Edge/Chromium, production build, ширины 1440, 768, 390 и 320 px.
- Проверены каталог, поиск, CTA, переход гостя к входу, вход, форма регистрации, профиль, корзина, количество, оформление, страница товара, избранное, фокус и reduced motion.
- API перехватывался в браузере. Данные товаров прочитаны из локальной БД в режиме read-only; профиль и заказ тестовые. Реальных заказов и аккаунтов тест не создаёт.
- Сквозная проверка Django не выполнена: локальный сервер не завершил запуск. Производительность на физическом слабом телефоне не измерялась.
- Next.js сообщил о медленной файловой системе E: и двух существующих lock-файлах. Сборку это не блокирует.

Скриншоты рядом с этим файлом показывают реальные компоненты с тестовыми API-ответами. `result.json` содержит итог браузерной проверки.

Повтор проверки: запустить production-сервер на порту 3001, задать `PLAYWRIGHT_MODULE` как путь к доступному модулю Playwright и выполнить `node design-review/smoke.cjs`. Пакеты в проект не устанавливались. `UI_BASE` позволяет выбрать другой адрес.
